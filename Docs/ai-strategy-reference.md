# 全角色 AI 策略与权重总表

2026-10-26，覆盖当前50个子职。本文整理生产AI正在使用的策略与数值；不把实验中未采纳的候选配置或图鉴操作建议写成已实现的AI能力。本次只整理策略，不改动AI算法及其权重。

## 阅读方式与来源

- **自身策略**：AI如何安排手值、运算、攻击和技能选择。
- **针对策略**：全局针对模型、开局对手修正和少量专属判断。各角色没有一个统一的“针对百分比”。
- **手值权重**：下文每名角色的0～9原始表；0权重为0。它不是直接伤害，也不是选招概率。
- **组合／技能分**：满足条件后直接加入评分，与手值缩放系数分开计算。同一走法可叠加多个项目。
- **机制应对提示**：从图鉴摘录给读者参考，不能据此断言AI已实现同等深度的战术规划。

核心来源：[走子与通用选择](../Assets/Scripts/Assistant/GreedyChoiceProvider.cs)、[手值与开局对手修正](../Assets/Scripts/Assistant/HandValueProfiles.cs)、[组合判定](../Assets/Scripts/Assistant/HandValueProfile.cs)、[当前模式配置](../Assets/Scripts/Assistant/ValidatedAiTuning.cs)、[新针对模型](../Assets/Scripts/Assistant/GreedyChoiceProvider.Counterplay.cs)、[集火表](../Assets/Scripts/Assistant/FocusPolicies.cs)。专属技能另见Assistant的Wizards、Martial、Druids、AncientRoles、LoreStormIllusion、ArcaneFive和TeamSupport分文件，以及[角色逻辑](../Assets/Scripts/Characters/SpecialLogics/)和[控制器](../Assets/Scripts/Assistant/BoardController.cs)。

## 1. 公共自身评分与优先级

走法总分由效果档位、角色额外分、运算后手值、组合奖励、下一手潜力、针对惩罚、目标优先级、集火及斩杀等相加。另有难度噪声与控制器先行选择。**自身系数12与针对系数43不代表12∶43，也不保证总决策为7∶3。**

| 项目 | 当前实现／权重 |
|---|---|
| 基础攻击档位 | 4→44；6→66；8→88。部分特殊效果再由角色接口修正；不是按最终实伤统一换算 |
| 合盾 | 50；角色另加技能分 |
| 普通回复 | 满血5；非满血且生命≤4为120；其余30 |
| 留牌偏好 | `((W[运算后手]+W[另一手]) / 10) × H`，先整数除法；H通常12，忍宗1v1为8 |
| 组合奖励 | 每条匹配后直接加完整Bonus，不除10、不乘H；多条匹配可叠加 |
| 下一手潜力 | 无组合规则的角色才计算；枚举留下的手与场上其他存活角色手值，取最佳普通效果分×120÷100。最高88×120÷100=105，代码注释“约10分／千分比”已过时 |
| 小项 | 加数手为完整盾+8；加数数字2再+5。加数本身通常不改变，不表示该盾被打碎 |
| 斩杀 | 预计可斩杀+100000；伤害预览涉及角色增伤、防御、抗性、免疫、易伤、屏障与虚假生命，仍是启发式 |
| 目标优先级 | 己方与队友均可达+10000；目标每少1%生命+100；无盾／太极+100；低防御再按`(10−clamp(防+5,0,10))×10`；攻击威胁加`clamp(攻+5,−10,10)` |
| 多人集火 | Self：优先离自己最近的敌人，同距取低生命，再取小座位；攻击该目标且可达+25000。仅一名敌人时不加 |
| 队友安全 | 攻击已知队友的惩罚参数10000；借队友手作加数本身不算攻击队友。具体目标／得分路径存在局限，见末节 |
| 难度噪声 | 简单±25，普通±8，困难0；是否启用由难度配置控制 |

手值例：破阵者运算后为5/1，原始95+60=155；留牌分为15×12=180，另加“持5”组合60与结果5技能28，共268。它们仍需与效果、目标及其他项目合计，不能只据这268分判断最终走法。

## 2. 公共针对模型与模式区别

### L：原情境针对模型

当前针对对象首先取**加数手主人**；加数是自己或队友时直接返回0。任一方生命≤40%才触发。令E为自己运算后两手在该对手原始表中的最高权重先乘42÷100；自己危险加一个E，对手危险再加一个E，最终扣`累计E×D÷100`。两种危险使用同一敞口估值，未分别推演“攻击机会”与“防守机会”。

若针对对象具有自加能力，另比较每只留牌与其归一化双手和：每超1点额外扣6，单手最多30；同样只在上述危险分支中生效。这是数值敞口近似，并非证明魔术师能造出所有较小数字。

### P：运算后机会预览模型

遍历全部存活、可行动且非已知队友的角色；用其每只可运算手，分别加自己运算后的两手。对每个结果给分：

| 机会 | 预览分 |
|---|---|
| 结果本身 | 对手原始手值权重÷4 |
| 攻击 | 对手能打到自己且未失能：自己≤40%生命+60，否则+24 |
| 合盾 | 对手≤40%生命+45，否则+15 |
| 回复 | 对手缺血且无腐朽：其≤40%生命+50，否则+15 |
| 对手组合 | 每条匹配加`min(40,组合Bonus÷4)` |

取所有敌方机会的最大值，扣`最大机会×D÷100`。常态也计算，不以低血作为开关；它不改状态、不消耗随机数。尚未完整模拟敌方下一回合全部技能、防御、额外攻击和选目标过程。

## 3. 专属选择共享评分

**元素基础分**：先以基础6加当前攻防估伤，再应用元素反应与免疫／抗性／易伤。免疫返回0；附加新状态且无圣光，寒冷+5、雷鸣+4、其余+3；估伤可击杀+15；强酸／毒素互遇已有另一状态再+2。四象的额外反应加分、龙脉／风暴的来伤抗性分以及奥法骑士／剑歌的元素均分，在各自条目另列。不同选择入口的免疫项处理不完全一样：ElementScore对免疫目标直接−100。

**组合真实含义**：ContainsAll要求列出的数字全部出现在两只手中，不是“其中一个”。例如“持8与6”必须8/6；要求三个不同数字的规则在当前两手机制下不会命中。SumEquals用取个位且0变1的运算判定；双手原始和10的勇士／德鲁伊条件另行处理。

**开局分配**：用本角色原始表，加下文面对目标的静态修正；修正后权重限制0～1000。先取自身最优15分以内的候选，再以`自身分×100−对手惩罚+后手克制分×10`择优。对手惩罚按候选余量限制，最多6；后手克制分来自四种加法组合能否命中自己比基线更重视的数字，以及对手总点数≥14时持5的防守奖励2。静态对手修正不直接加入局中HandValueScore，也不是修改对方的手值表。

## 5. 当前实现的边界

这份表是代码快照，部分注释和图鉴建议比实际算法更理想化，需区别阅读：

1. **没有固定“自身／针对占比”**。H、D、斩杀和目标优先级量纲不同；100000斩杀、25000集火与10000级目标分通常远大于手值微调。身份局还有更大的身份优先级，不能简单说斩杀永远最高。
2. **L模型不枚举敌人实际运算**，而且以加数主人为对象；借己方手时没有该项针对惩罚。P才预览运算后敌方机会，仍不等于完整下一回合搜索。
3. **目标评分与实际目标有路径差异**：意图目标解析允许借队友手攻击敌方，但部分目标／集火评分仍直接取加数主人；不可把“有安全惩罚参数”理解为所有借手情形都被完全等价评价。
4. **三数字ContainsAll不会触发**：咒法以外的部分旧组合说明写“4/6/8任一”等，代码实际要求全部。本表保留真实条件和分数，没有在整理文档时修改玩法／AI。
5. **塑能放弃随机数表达式**是`(_wizardSeed >> 16) & 0x7FFF % 100`。按C#优先级等于右移值与`(32767%100)=67`按位与，结果只在0～3、64～67，故阈值60／30／10不能解释为实际概率60%／30%／10%；三者当前接受区间相同。这里仅记录现状，未改算法。
6. **塑能选型并没有遍历所有注释列举的类型**：当前有效分支主要为力场／暗蚀／毒素／寒冷／闪电。危险先返回寒冷，多人分支后面的危险光耀路径不会到达。针对赌徒的阶段辅助函数也未被主评分调用。
7. **部分技能是明确的简单规则**：奥法免费复制固定接受；勇气学院取首名敌人且单目标；防护先选最低绝对生命者；守望者锁手复用首候选主人的表。都不应写成“全局最佳选择”。
8. **特殊改写并非统一实伤评分**：部分基础档位及斩杀入口仍先识别普通4/6/8，然后另用接口修正。巨人5、狂战9、奉献4/6等不能只看第一张公共档位表推断最终行为；真实攻击／治疗规则仍以[RULES](../RULES.md)为准。
