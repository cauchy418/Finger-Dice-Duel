# AI状态策略与统一入口

所有58个子职的自身走法与对手机会共用此层。25种负面状态、4种枚举角色状态及35类非计时效果均显式登记；剑歌、醉拳也在非计时效果入口中，因此游戏仍为6类角色状态，没有新增战斗状态。

## 读取与扩展

实现位于[AiStatePolicy](../Assets/Scripts/Assistant/AiStatePolicy.cs)，调用位于[状态动作适配](../Assets/Scripts/Assistant/GreedyChoiceProvider.StatePolicy.cs)。职业技能评分保留；手值表复制后叠加状态偏好，动作按实时结果、预计伤害、实际治疗目标和合法攻击判断；目标修正另走`ScoreTarget`。状态到期或效果解除后自动停用。

- `AiStateRule`：稳定键、激活条件、攻击／回复／合盾／准备／目标敞口五项偏好，及可选动作回调。
- `AiStatePolicy.Register(rule)`：在启动阶段登记或覆盖同一稳定键，即可供所有角色和模式读取。计时状态键使用`status:<枚举数值>`，避免兼容别名更改字符串。
- `ApplyHandWeights(basis, owner, game)`：返回副本；按数字在当前角色下的效果，将对应偏好÷3加到手值，沿用手值表非负限制。原表、其他角色与下一局不被修改。
- `ScoreMove(AiStateContext)`：只读当前运算、角色与目标、预计伤害／回复及可达性，叠加动作偏好和回调。总修正限制为−600～300，不替代斩杀、团队与身份规则。
- `ScoreTarget(owner,target,game)`：当前对手的敞口偏好合计限制为−160～160；失明时避开未失明的目标，仅自己的暗劲来源后续命中有额外优先。

纯运算只按手值与后续机会估值，不领取攻击／回复／合盾的即时收益。魅惑仍由公共流程随机行动；冻结仍禁止行动。这里改变AI偏好，不改变游戏合法性或伤害公式。

## 优先级与验证

运算结果使用Core只读预览，覆霜、潮湿、困惑只处理一次；王车／预兆等已准备结果被保留，纯预览不执行技能、不消耗资源、不推进战斗随机源。对手机会及未来运算同样使用实际状态修正，并过滤目盲、暗置和被加数限制。

无合法攻击、无实际治疗收益、耳鸣不能合盾等限制优先于普通偏好。生命领域4/6/8按AI实际的治疗选择投影，使用对应回复量；先净化再治疗，不能把腐朽、耳鸣、圣火误当作禁疗。给其他角色治疗不错误套用施法者自身的禁疗或灼伤罚分。满血净化、溢出赐福、知识祝福及战争祝福分别检查是否真实有效。

12项状态专项包括58×25个角色／负面状态组合的无副作用检查、多状态、到期恢复、全局表隔离及真实评分回归；7项角色专项覆盖错误技能决策。功能回归1724项、UI与Unity/NUnit编译通过，统计工具另有6项独立校验。胜率与分母只在[本轮报告](../Tools/Statistics/2026-11-10-identity/README.md)和[图鉴](roster.md)列出。

当前修正是可解释的启发式。多回合搜索、最优资源价值、状态组合的长期收益仍有改进空间；本轮不以同一批循环赛重新挑权重，也不将旧低胜角色的变化全部归因于这次AI修改。
