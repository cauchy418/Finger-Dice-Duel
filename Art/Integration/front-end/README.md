# 前台运行时美术接入

2026-10-21。主菜单及其现有的全部菜单、五种选将界面、图鉴与先攻流程现已使用前台美术资源。直接在团结引擎内 Play 即可，所有 UI 仍由代码创建，无须拖拽引用或设置场景。

## 页面范围

- 主菜单：三大模式、角色图鉴、伤害与状态手册、规则、退出。
- 子菜单：冒险、竞技、娱乐、1v1、2v2、入门／经典、难度、8 人模式、阵营混战、身份对局、双将、双将对决、双将阵营混战。
- 选将：1v1 双方、2v2 自己与队友、8 人阵营、8 人身份、双将主副将；双将阵营混战共用选将并保留独立提示。
- 图鉴：24 人总览、详情、左侧角色列表、阵营双轴筛选、循环翻页、长正文滚动；魔法球仍单独进入 13 种伤害／9 种实际状态两页手册。
- 先攻：1v1 双骰与 2v2 四骰、实时点数、减速摆动、结果文字、合法拆分、翻转、AI 自动分配及完成回调。
- 模态页面：完整规则与所有未开放功能的提示弹窗，保持遮挡和关闭行为。

冒险关卡、联网与设置等未实现的功能没有因换皮被宣称开放；既有占位入口继续显示说明。对局中的多人与单挑界面不由这套前台换皮重建。

## 实现与维护

`GameBootstrap.FrontEnd.cs` 管理背景和选将布局；`FrontEndArt.cs` 缓存纹理、九宫格与五态 Sprite；`CharacterRosterView` 保留名单替换与 SelectionChanged 接口，显示绘画徽记网格，属性和短技能保留在详情与悬停提示中。`CodexScreen` 使用入口转换后的扁平数据，未向 UI 引入 Characters 依赖。

背景按 16:9 等比 Cover；CanvasScaler 使用 Expand，以保住 1920×1080 设计区。绘画主体不乘色，职业徽记不重复加圆框。标题使用思源宋体静态字体，正文使用 Noto Sans CJK，骰面数字独立实时渲染。所有新 meta 均由引擎导入生成。

骰子制作来源与完整提示词在 `Art/Production/initiative-v1/`。先攻状态、取随机数、座位判定、合法拆分、信息优势和 AI 分配继续由既有 Assistant 控制器决定。UI 不创建 HandSplit，不追加决定游戏结果的掷骰；大失败说明修正为准确区分投骰者与代为指定者，并有 1／20、20／1、1／1 的文字回归测试；2v2 新动画只播放控制器已经取得的点数。

## 编辑器验收

菜单 **Finger Dice Duel → Preview → All Front End Art** 可重复运行实际 UI 检查。它进入 Play，验证真实 GraphicRaycaster 命中后派发点击，检查菜单按钮边界与重叠、24 人网格、选择回调、同阵营副将、2v2 座位控件、身份局保留角色、图鉴分页筛选、伤害／状态资源、先攻结果和最多 45 个候选。验证期间临时启用 runInBackground，结束后恢复原值；最小化的编辑器用实际相机渲染建立 Graphic 深度，离屏截图切回 Overlay 后再检验命中，超时即失败。

`validation.txt` 记录每条引擎断言；同目录 PNG 为 **Unity 运行时 Canvas 实际渲染图**，不是静态拼装稿。`main-game-view.png` 另由 ScreenCapture 获取当前 Game View，尺寸取决于编辑器窗口。MainMenu 另有 1366×768 与 1920×1200 尺寸检查。测试注入的 20／1 和 2v2 固定点数只在 Editor 预览工具中出现，正式 UI 不固定随机数。

Core 无头测试、FDD_UNITY_TESTS 编译、UI 编译与组件冲突检查仍须按 CODELY.md 运行；它们不能替代本目录的画面与交互验收。
