# 手指骰子对决 · Finger Dice Duel

一款 2D 回合制对战游戏：双方各自用两只手（初始数值均为 **1**），
每回合用**自己的一只手**与**对方的一只手**相加，结果按十进制取个位
（和为 10 时变成 1），结果的数字决定这一手的效果。

> **引擎**：团结引擎（Tuanjie，Unity 中国版）`2022.3.62t15`
> **语言**：C# ｜ **UI**：uGUI + TextMeshPro ｜ **渲染**：内置管线

## 核心规则速览

每回合的运算：

```
自己的一只手  +  另一名玩家的一只手  →  取个位（和为 10 → 1）
```

**只有行动方的手会改变**（对方那只手只是"被加的数"）。

| 结果 | 效果 |
|:---:|---|
| **4 / 6 / 8** | **攻击** —— 对目标造成该点数伤害 |
| **9** | **回复** —— 自己回 9 点生命 |
| **5** | **合盾** —— 这只手成为护盾，可挡下一次攻击 |
| **1 / 2 / 3 / 7** | 无效果 |

- 初始生命 **20**，先归零者败。
- **轮次上限**：所有模式统一 **50 轮**（1v1 = 100 回合、2v2 = 200 回合）；
  打满后**按血量判定**（1v1 比个人血量，2v2 比队伍总血量），相同才平局。
- **攻击伤害 = 基础值 + 攻击方攻加成 − 防守方防加成**（最低 0）。
- **护盾**可完全挡下一次攻击（不受伤），挡完即碎。
- **攻击距离**：到对方在**座位环**上的最短距离（阵亡者从环上摘掉）。
  大多数角色是 **1**；**咒术师 / 牧师 / 妖术师 / 术士 / 邪术师无限**；
  **魔射手 / 吟游诗人 3**；**骑士随碎盾成长**。

> 📖 **完整规则见 [`RULES.md`](RULES.md)** —— 它是本项目的规则权威文档，
> 代码、测试、UI 都必须与它一致。

## 玩法模式

| 模式 | 说明 |
|---|---|
| **1v1 入门** | 不掷骰，双方从 1/1 开始。可选 **AI 难度**（简单 / 普通 / 困难） |
| **1v1 经典** | 掷 **1d20** 决定初始手值与先手。不提供难度选择 |
| **2v2 入门** | 四人同场，**座位由玩家选**。固定**困难** AI，无难度界面 |
| **2v2 经典** | 四人同场，**四人各投 1d20 决定座位**（不选座位），再按先攻顺序分配手值 |
| **双将对决（1v1）** | **娱乐模式**：每人由**同阵营的两名角色**合体上阵（攻防**相加**、其余取优）。掷骰流程与经典一致 |

**双将对决**（娱乐模式）：玩家**只选自己的两名角色**，对手由 AI **随机搭配**。
两名角色必须**同属守序 / 中立 / 混乱之一** —— 这样能保证"接管型"技能互不冲突。
主将名进战报，标题栏列出两名。

| 项 | 规则 |
|---|---|
| **合并方式** | 攻 / 防 **相加**；生命 / 距离 / 段数 / 斩杀线 **取最大**；AI 评分取较优者 |
| **技能** | 两名角色的技能**都生效**（生命周期钩子逐个转发） |
| **接管型技能** | 改写 / 取消 / 闪避等"接管同一步骤"的接口**取第一个能处理的** —— 同阵营保证不重叠 |
| **胜率参考** | 见下方「[双将模式平衡实测](#双将模式平衡实测)」 |

**2v2 座位与队伍**：环形座位 1–4，**1&4 一队、2&3 一队** ——
所以**队友永远相邻**。主视角可以坐在任意座位。

**2v2 先攻流程**（经典）：

```
四人各投 1d20 → 大数较大的那一队坐 1 号位与 4 号位 → 按 4 → 3 → 2 → 1 依次决定手值
  · 大失败（1）最先：由配对的对手替他决定（完全自由）
  · 大成功（20）最后：各自决定
  · 后决定的人能看到前面人决定的数字
```

**2v2 的运算源**：合法加数是**任何其他玩家**的手（**含队友**）；
**攻击目标也可以是队友**（所有模式队友都是合法目标）。
攻击目标在**第 ③ 步单独选**，可以与被加数的手主不同。

## 开局掷骰（1d20）

开局双方各投 **1d20**，点数 = **两只手初始点数之和**，玩家在**合法拆分**里自选
（合法 = 两手都在 1..9 且之和为 N）。点数小的先分配、大的后分配；同点数同时分配。

| 点数 | 特殊效果 |
|:---:|---|
| **1** | **大失败** —— 由对手替你指定初始手值 |
| **19** | **小成功** —— 一只手必须是 9，另一只手随意 |
| **20** | **大成功** —— 两只手完全随意 |

> **信息优势**：后决定的一方看得到先手方的选择，可以针对性应对（点数大 = 后选但信息多；点数小 = 先选但信息少）。双大失败时互不知情。

> **先手**：点数**大**的一方先出招（与"点数小先决定手值"互补）。
> 掷骰前先进 1v1 选玩法：**入门**（不掷骰，双方从 1/1 开始）/ **经典**（掷 1d20 决定初始手值与先手）。
> 入门的人机对战还可以选 **AI 难度**（简单 / 普通 / 困难）；经典玩法不提供难度选择。
> （点数大 = 后选但信息多；点数小 = 先选但信息少）。双大失败时互不知情。

> ⚠️ **初始手值不触发任何效果** —— 初始的 5 不是护盾，刺客初始双 7 也不进潜行。

## 交互流程

一次运算分**三步点击**（多人模式预留，1v1 也要求点完）：

```
① 点自己的手            → 选定"运算源"
② 点另一名玩家的手      → 选定"加数"（它参与相加；2v2 里队友的手也可以）
③ 点目标玩家的手牌      → 确认"打谁"（可与第 ② 步不是同一个人）

   挨打的是【玩家】，不是手 —— 手牌只是"指定目标"的载体。
```

**第 ③ 步只在结果会产生"指向别人"的效果时才出现**：

| 结果 | 是否要求确认目标 | 原因 |
|---|:---:|---|
| 4 / 6 / 8（攻击） | ✅ | 指向对手 |
| 9（回复） | ❌ | 默认回自己（**只有牧师**需要选人） |
| 5（护盾） | ❌ | 作用于自己 |
| 1 / 2 / 3 / 7 | ❌ | 无效果 |

**没有合法攻击目标时**（刺客潜行中不能被攻击、攻击距离不足），右侧只提供 **「放弃攻击」**
—— 放弃 = 运算照常发生（手值保留）、当次不造成伤害、**算用掉本回合**。

**所有按钮统一贴在「当前该做决定那位」的手牌右侧**（跳过回合 / 开赌 / 发动 / 不发动），
用世界坐标定位，1v1 与 2v2 共用同一套 —— 不会压住手牌或战报。

> **跳过回合**：刺客潜行、双盾在手、妖术师（体力不满且有人体力与自己不同）可以跳过。
> 妖术师的跳过会先让你**点一个人的手**，把那人的体力改成与自己一致。

## AI 与平衡

### 决策层次（数值由高到低，字典序）

| 档位 | 分值 | 依据 |
| --- | ---: | --- |
| **斩杀优先** | 100000 | 能一击带走时，其他一切都不重要 |
| **集火（focusSelf）** | 25000 | 2v2：优先打离自己最近的敌人；默认启用，4 个角色例外 |
| **目标优先级** | 10000 起 | 2v2 六级顺序：双方都能打到 > 血低 > 无防御 > 防低 > 攻高 |
| **下一手潜力** | ≤ 120 | 运算后留下的两只手，下一手能打出什么 |
| **情境化阻挡** | ≤ 16 | 血量低时才生效，见下 |
| **我方价值** | ≤ 12 | `HandValueProfiles` 的权重缩放后 |
| **效果档位** | 44~88 | 4/6/8 攻击、5 合盾、9 回复 |

### 2v2 集火策略（对照实验结论）

`GreedyChoiceProvider.FocusPolicy` 三档：`None` / `Self`（打离自己最近的敌人）/
`Mate`（打离队友最近的敌人，打不到则不生效）。集火分**只加在攻击上**，且目标必须可达。

**实验**：24 角色 × 600 局 × 2 段种子 × 3 组 = **86,400 局**；
同局三组共享阵容 / 初始手值 / 术士骰子。完整 24 行见
[`Tools/focus-report.txt`](Tools/focus-report.txt)。

| 结论 | 数据 |
| --- | --- |
| **focusSelf 总体 +3.2 点** | 49.8% → 53.0%；14 个角色显著提升、3 个显著下降 |
| **focusMate 总体 +0.1 点** | 远弱于 Self，不采用 |
| focusSelf 显著变差 | **狼人 -4.1**、法师 -3.3、猎人 -2.7；巨人 -2.5（不显著） |

提升最大的：**邪术师 +17.7、刺客 +9.2、忍者 +7.3、野蛮人 +6.8、
战士 +6.3、武僧 +6.3、游侠 +4.4、士兵 +3.9**。

生产策略（[`FocusPolicies.cs`](Assets/Scripts/Assistant/FocusPolicies.cs)）用**黑名单**：
默认所有角色 `focusSelf`；**猎人 / 狼人 / 魔术师 / 邪术师**保持 baseline。
邪术师自己用 Self 是 +17.7，但 2v2 已 **62.5% / 平局 8.7%**，先处理平局再叠加集火。

> 集火分必须加在 `ScoreMove` 的**攻击分支**，不能放进 `TargetPriorityScoreFor`
> （那个函数也被合盾 / 回血调用）；1v1 直接返回 null，否则所有攻击会偷偷 +25000。

### 情境化阻挡（3 : 7）

- **自己**血量低于 40% → 大幅阻挡对手凑出**攻击**数字
- **敌方**血量低于 40% → 大幅阻挡他凑出**盾 / 闪避 / 太极 / 回复**数字
- 阻挡的减值**永远不超过**自己合成的收益 ——

  > 这是**结构性保证**：阻挡是对"对手价值"的缩放，
  > 所以比率 `DenyRatioPercent`（默认 43）一定让它落在 3 : 7 附近。

### 角色专属策略

| 机制 | 用于 |
| --- | --- |
| `IAiMoveAdvisor` | 给"这一手"加分（圣武士合盾、战士合盾…） |
| `ITwoStepGoal` | **多回合计划**：刺客凑双 7、剑客凑双 4/6/8 |
| `ILethalThresholdAdvisor` | **斩杀线**按自己的机制重算（游侠 ×1.5、剑客追加、巨人两段、刺客 +7） |
| `IHealTargetAdvisor` | 牧师该给谁回血（2v2 优先一队血量最低的） |
| `ISkillUseCounter` | 让"技能发动率"可测量（潜行 / 锁手 / 取消攻击…） |

**法师的 AI（"放弃攻击换伤害类型"怎么选）**：

| 合出 | 放弃概率 | 依据 |
|---|---:|---|
| 4 | 60% | 玩家原话"**倾向**于放弃" |
| 6 | 30% | "**不一定**会放弃" |
| 8 | 10% | "**基本不**放弃" |

> ⚠️ 概率**必须收敛**：把 4 设成 85% 时法师会**永远在铺垫、永远不出手**，
> 类型反而被"消耗它的那一次攻击"白白吃掉 —— 胜率反而更低。
>
> **选类型**（按局面的优先级）：
> · 能斩杀 → 有盾用**力场**（穿透必中）/ 能回血用**暗蚀** / 否则用**毒素**（带状态）
> · 自己危险 → **寒冷**（结果减半）
> · 多人局 → **闪电**（感电波及相邻）
> · 对手能回血 → **暗蚀**
> · 其余 → **毒素**
>
> ⚠️ **力场不能当兜底**：它**不挂任何状态**，选了等于白扔一回合。

## 8 人身份对局

**身份**：主公 1、忠臣 2、反贼 4、内奸 1；主公固定 1 号位，其余身份随机分到 2–8 号位，
所有座位在选角阶段就可见。主公体力上限 **+5**。

- 主公先选角色，其他玩家可以看到主公选角；其余角色由 AI 从剩余角色中随机补齐。
- 人类玩家的身份随机（AI 练习），因此既可能当主公，也可能当忠臣 / 反贼 / 内奸。
- **身份可见性**：主公身份始终显示在座位左上角；其他身份隐藏，玩家阵亡后公开；
  人类自己的身份对自己可见。
- **胜负**：
  - 主公 / 忠臣：反贼和内奸全部阵亡；
  - 反贼：主公阵亡（主公死时只要还有忠臣，反贼即胜，即使反贼已全灭）；
  - 内奸：忠臣与反贼全部阵亡后，主公阵亡。
- **击杀奖惩**：任何玩家击杀反贼 -> 额外行动 X 次（X = 剩余反贼数）；主公击杀忠臣 ->
  从主公下家开始，所有存活反贼按座位各行动 1 次；不推进轮次，可嵌套，战报记录。
- **反贼嫌疑**：攻击主公 -> 大幅怀疑；攻击范围内有大幅嫌疑目标却打别人 ->
  小幅怀疑；后来持续攻击被怀疑目标 -> 怀疑降低。主忠方优先攻击范围内最被怀疑的人。
- **击杀反贼**：额外行动 X 次，X = 击杀后场上剩余反贼数（不再是固定 1 次）。
- **主公防守权重**：反贼死亡不足 2 人、且无法斩杀反贼时，主公 AI 大幅提高合盾 / 回复评分。
- **内奸行为**：反贼阵亡两人前与主忠方同轨迹；之后只有在主忠方存活人数大于反贼方时
  才开始攻击忠臣；所有忠臣和反贼阵亡前不攻击主公。

> ① 盗贼 AI 选到自己的手后 `ExecuteSteal` 抛异常，控制器停在 `ChoosingStealTarget`；
> ② 强制赌博的 AI 进入选目标阶段时 `_selectedTarget` 为空，无法确认目标。
> 两者均已修复；剩余 2 局都是“选中被锁的自己的手”的边缘情况。

## 工程结构

`Core`（规则内核）/ `Characters`（24 角色）/ `Assistant`（状态机 + AI + 整局驱动）/ `UI`（唯一引用 Unity 的层）。
依赖方向：`UI → Assistant → Core`，`Characters → Core`；`Tests` 970 项无头测试。
详见 [CODELY.md](CODELY.md)。

## 角色图鉴

主菜单右上角的「图」按钮（问号下方）进入图鉴：可翻页的卡片，
每张依次显示**名称（中英文）、阵营、生命 / 攻 / 防 / 距离、
技能（一句 + 详细）、操作指导、如何针对、与其他角色的特殊交互**。

- 攻击距离为无限时显示为 **∞**（代码里是 `int.MaxValue`）。
- 「阵营筛选」按钮在「返回」正下方，点开才弹出九宫格按钮；
  **两条轴可以依次叠加**（再点一次取消）。
